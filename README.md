# تطبيق مندوب المبيعات (أندرويد) — يعمل بدون إنترنت

تطبيق مكتوب بـ HTML/JS ومغلّف بـ Capacitor لينتج ملف APK. كل البيانات تُحفظ داخل الجهاز (IndexedDB)
فيعمل بالكامل بدون شبكة. لا يحتاج أي خادم للتشغيل.

## الرقم السري الافتراضي للمشرف: 1234  (غيّره من الإعدادات)

## 1) تجربة سريعة بدون APK (على الكمبيوتر)
    cd www && python3 -m http.server 8123
ثم افتح http://localhost:8123 (يفضّل بوضع الجوال في المتصفح). من «المزيد ← الإعدادات ← تحميل بيانات تجريبية».

## 2) بناء APK بدون Android Studio (الأسهل): GitHub Actions
1. أنشئ حساباً على github.com ومستودعاً (Repository) جديداً.
2. ارفع كل ملفات هذا المجلد للمستودع (بما فيها .github).
3. من تبويب Actions اختر «Build APK» ثم Run workflow. بعد 5–10 دقائق نزّل `rep-app-apk` من نتيجة التشغيل.
4. انقل app-debug.apk للهاتف وثبّته (فعّل «التثبيت من مصادر غير معروفة»).

## 3) بناء APK على جهازك (Android Studio)
    npm install
    npx cap add android
    # أضف صلاحيات CAMERA و ACCESS_FINE_LOCATION و ACCESS_COARSE_LOCATION في android/app/src/main/AndroidManifest.xml
    npx cap sync android
    npx cap open android      # ثم Build > Build APK
(يتطلب Node 20+ و JDK 21 و Android Studio)

بعد أي تعديل في مجلد www نفّذ `npx cap sync android` ثم أعد البناء.

## تغيير الاسم/الهوية
- اسم التطبيق ومعرّفه: capacitor.config.json (appId / appName). غيّر appId قبل أول بناء.
- أيقونة التطبيق: استخدم Android Studio ‹ New › Image Asset.

## ما الذي يغطيه التطبيق (مطابق لقائمتك)
| البند | في التطبيق |
|---|---|
| شحن العربة | المخزن ← شحن العربة |
| مزامنة المخزن مع العهدة | كل بيع/مرتجع/إلغاء يحدّث رصيد العربة تلقائياً (سجل حركات) |
| أسعار جملة/قطاعي/كميات | الأصناف + نوع العميل + أسعار الكميات (12:9000, 24:8800) |
| فاتورة فورية كاش/آجل/تحويل/مختلط | شاشة بيع + مشاركة (واتساب...) + طباعة |
| سداد بالتحويل البنكي | رقم العملية + صورة + حالة (قيد المراجعة/مؤكد/مرفوض) + منع تكرار الرقم |
| خط السير والزيارات | يوم الزيارة لكل عميل، زيارة بدون بيع مع السبب، موقع GPS مع كل فاتورة/زيارة |
| المرتجعات | من العميل (خصم دين/رد نقدي/تالف) + إرجاع العربة للمخزن الرئيسي |
| التسوية اليومية | نقد متوقع vs فعلي + جرد العربة + عجز/زيادة يُرحَّل لمديونية المندوب |
| الديون والتحصيل | رصيد العميل، سقف الدين، مواعيد الاستحقاق، المتأخر، سندات قبض |
| المصروفات | تصنيفات + صورة إيصال، وتُخصم من نقد التسوية |
| ملخص الخزينة | كاش / تحويلات / آجل منفصلة |
| أوفلاين | كل شيء محلي؛ المزامنة اختيارية |
| إضافات | صلاحية مشرف بالرقم السري، سجل تدقيق لإلغاء الفواتير، تالف/عينات، عمولة وهدف، تنبيهات، نسخ احتياطي |

## حدود الإصدار الحالي (للصراحة)
- **لم يُجرَّب على جهاز أندرويد حقيقي** من طرفي؛ جُرّب منطق التطبيق وواجهته في متصفح آلياً. أول بناء قد يحتاج تعديلاً بسيطاً حسب إصدار Capacitor/Gradle.
- **الطباعة**: المتاح مشاركة الفاتورة كنص (واتساب/رسائل) وطباعة النظام. الطباعة المباشرة على طابعة بلوتوث حرارية (ESC/POS بالعربي) تحتاج إضافة (plugin) ومعالجة للخط العربي — مرحلة تالية.
- **لا يوجد خادم مركزي**: بيانات كل مندوب على هاتفه. ملف `www/js/sync.js` جاهز لمزامنة مع خادم تبنيه، بالعقد التالي:
  - `POST {serverUrl}/sync` بجسم `{rep:{code,name}, data:{invoices:[], payments:[], ...}}`
  - `GET {serverUrl}/master` يرجع `{products:[], customers:[]}` (الأصناف والعملاء تأتي من المكتب)
  أرقام الفواتير تبدأ برمز المندوب (R1-INV-00001) لتفادي التعارض بين المناديب.
- **تتبّع الموقع** يُسجَّل عند الفاتورة/الزيارة وليس تتبعاً مستمراً في الخلفية.
- **التأكيد المحاسبي للتحويلات** يتم حالياً من نفس التطبيق بالرقم السري؛ في النظام المركزي يُفضَّل أن يؤكدها المحاسب من لوحة المكتب.
- الباركود: يدعم إدخال/قارئ باركود خارجي (لوحة المفاتيح)، بدون كاميرا مسح.
- الدفعات تُخصم من أقدم فاتورة آجلة أولاً (FIFO) ولا تُربط بفاتورة محددة.
